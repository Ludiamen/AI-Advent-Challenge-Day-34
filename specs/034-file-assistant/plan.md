# День 34 — ассистент для работы с файлами проекта: план

Как строится то, что описано в [spec.md](spec.md). Задачи — [tasks.md](tasks.md).

## 1. Архитектура

```
 cli.py --файлы «цель»           /chat: /files цель            check_files.py (набор целей)
            └──────────────┬──────────────┘
                           ▼
   agent/files/task.py     Задача: цель, проект, база, ветка, журнал вызовов, находки, черновик,
                           решение человека, коммит; хранилище memory/files/tasks/<id>.json
                           ▼
   agent/files/assistant.py  цикл: модель (llm.Client, function calling) ⇄ инструменты files
                           (≤ 12 кругов, предел токенов) → итог JSON → проверка кодом (check.py)
                           ▼
   files_server.py (MCP, stdio; в процессе — mcp.Client(server))
     чтение: files_list · files_read · files_search · files_outline · files_log · files_show
     черновик: files_create · files_edit · files_draft_diff        (на диск не пишут)
                           ▼
   agent/files/workspace.py  клон проекта (git clone --local) на базовом коммите; ветка задачи;
                           применить черновик (git apply) → коммит; отклонить
```

## 2. Решения

- **D-01. Рабочая копия.** `projects.json` получает у проекта `база` (коммит) и
  `копия` (каталог клона, по умолчанию `memory/files/<проект>`). `workspace.подготовить()`:
  если клона нет — `git clone --local --no-hardlinks <путь> <копия>`; затем `fetch` из
  оригинала, `checkout --detach <база>`, очистка (`reset --hard`, `clean -fd`). Ветка задачи
  `assistant/<id>` от базы создаётся при «Применить». Клон — самостоятельный репозиторий:
  в `.git` оригинала ничего не пишется (worktree бы писал). До и после прогонов
  `check_files.py` сверяет HEAD и `status --porcelain` оригинала (NFR-02).
- **D-02. MCP-сервер `files_server.py`.** По образцу `git_server.py`: `--корень`, проверка
  пути (`realpath` внутри корня, не `.git/`, не `.env*`, не симлинк наружу, не из
  `ЗАКРЫТО` — ключи, сертификаты), предел чтения 60 000 символов / 400 строк за вызов,
  бинарные — отказ с причиной. Инструменты:
  - `files_list(pattern="**/*.py", limit)` — файлы под git (`git ls-files`) по шаблону
    fnmatch; размер и число строк;
  - `files_read(path, start=1, end=0)` — строки с номерами;
  - `files_search(query, regex=False, glob="", limit=200)` — `git grep -n` (фиксированная
    строка или регулярка), результат: файл, строка, текст строки; `слово=True` — границы
    слова, как в Дне 32;
  - `files_outline(path)` — Python: `ast` (классы, функции, строки); markdown — заголовки;
    JSON — ключи верхнего уровня;
  - `files_log(path="", limit=20)`, `files_show(commit)` — история (только чтение);
  - `files_create(path, content)` и `files_edit(path, old, new)` — **в черновик** задачи:
    сервер держит черновик в `FILES_DRAFT` (JSON рядом с задачей); `edit` требует ровно
    одно вхождение `old` в текущем содержимом (база + черновик) — иначе ошибка с числом
    вхождений; `create` — только новый путь;
  - `files_draft_diff()` — единый diff черновика против базы.
  Аннотации MCP: чтение — `readOnlyHint`; черновик — `destructiveHint=False` (меняет только
  черновик). Удаления, команд, записи на диск у сервера нет вообще.
- **D-03. Ассистент (`agent/files/assistant.py`).** Цикл как у ассистента Дня 31 (`КРУГОВ`,
  function calling через `llm.Client`): системный промпт — проект (описание из
  `projects.json`, оглавление верхних каталогов), правила (сам находи файлы; читай перед
  правкой; находка = файл + строка + дословная цитата; правки — только `files_create` /
  `files_edit`; секреты не читай), четыре вида целей с подсказками, что обычно нужно
  (без имён файлов). Предел: 12 кругов, 120 000 входных токенов на цель; при пределе — итог
  по собранному. Итог — JSON: `{"итог": текст, "вид": использования|документация|adr|правила|другое,
  "находки": [{"файл","строка","цитата","роль"|"правило","суть"}], "правки": описание}`.
- **D-04. Проверка кодом (`agent/files/check.py`).** Находка: файл существует в базе,
  строка в пределах, цитата найдена в строке ±3 (`cite.найти`) — иначе «не подтверждена»;
  дубли сливаются. Черновик: `git apply --check` на базе; пути — разрешённые; изменённые
  файлы были прочитаны (журнал `files_read`) — иначе пометка «правка без чтения».
  Для ADR: frontmatter по `docs/sdd-process.md` (id, вид, статус, версия, зависит_от,
  подпись), разделы «Контекст / Решение / Альтернативы / Последствия» (как ADR-0011); если в копии есть
  `tools/sdd.py` — запуск `проверить` на копии с применённым черновиком во временном
  каталоге: число ошибок не растёт.
- **D-05. Подтверждение.** Как заявки Дня 17: задача с непустым черновиком — статус
  «ждёт подтверждения»; `применить(id)` — `git checkout -b assistant/<id> <база>`,
  `git apply`, `git commit` (автор — «Ассистент файлов», сообщение — цель + итог);
  `отклонить(id, причина)` — статус «отклонена». Применённую задачу повторно применить нельзя.
- **D-06. Консоль.** `cli.py --файлы «цель» [--проект crm] [--модель ds-pro]` — ход по
  кругам (`· круг 2: files_search «notify»… 14 мест`), итог, находки, diff (цветом в
  терминале), вопрос «Применить? [д/Н]» только в диалоге; в неинтерактивном запуске —
  «задача N ждёт подтверждения: --файлы-применить N». `--файлы-задачи`, `--файлы-показать N`,
  `--файлы-применить N`, `--файлы-отклонить N «причина»`, `--файлы-повторить N`,
  `--файлы-метрики`.
- **D-07. Веб.** `/files цель` в мини-чате `/chat` (как `/review` Дня 32): SSE-ход по
  кругам, карточка: итог, находки (файл:строка, цитата, ✓/❔), diff с подсветкой
  (+/−), кнопки «Применить» / «Отклонить» (POST `/api/files/<id>/apply|reject`); после
  применения — ветка и коммит. Справка `/help`.
- **D-08. Журнал и повтор.** `memory/files/tasks/<id>.json`: цель, проект, база, модель,
  вызовы (имя, аргументы, размер результата, без содержимого), находки с проверкой,
  черновик (diff), статус, решение, коммит, метрики. `повторить(id)` — новая задача с той же
  целью и базой; сравнение: затронутые файлы (Jaccard), находки (файл:строка) — печатается.
  Повтор применения — `git apply` того же diff на чистую базу (проверка).
- **D-09. Метрики (`agent/files/metrics.py`).** `memory/files/metrics.jsonl`, белый список
  полей, сводка p50/p95, доля целей с правками, применено / отклонено.
- **D-10. Контрольный набор (`files-goals.json`) и ветка случаев.** Как `review-cases.json`
  Дня 32: на базе в клоне строится ветка `cases/day34` из посеянных правок (код, а не
  модель): новый маршрут в `urls.py` без строки в справочнике документации; два документа
  с устаревшим именем функции; пять нарушений конституции (запрещённое слово стека,
  секрет в коде, …) — по видам из `docs/constitution.json`. Цели (≥ 10): использования
  (3 — модель, функция, шаблонный тег), документация (2), ADR / changelog (2), правила (3).
  Эталон — кодом: `git grep` по идентификатору; список посеянных расхождений и нарушений.
  Оценка: код (полнота, выдумки, применимость diff, формат ADR) + судья ds-pro (суть и
  качество текста правок). Прогоны × 2, сравнение затронутых файлов.
- **D-11. Модель.** ds-flash по умолчанию, `--модель ds-pro`; судья — ds-pro. Локальная —
  вне рамок дня (цикл с инструментами на CPU идёт минутами).
- **D-12. ПД и секреты.** Ответы и журнал — маска ПД (профиль «точный», как Дни 31–32);
  `ЗАКРЫТО` в сервере: `.env*`, `*.pem`, `*.key`, `secrets/`, `deploy/**/.env*`.

## 4. Доказательный прогон `check_files.py`

1. Копия: клон, база, HEAD и статус оригинала до/после. 2. Сервер: границы путей
(`..`, `.git`, `.env`, симлинк), пределы, черновик не пишет на диск, `edit` с 0 и 2
вхождениями — ошибка. 3. Ветка случаев: посеянные правки на месте. 4. Набор целей × 2
(SC-07): по сценариям — полнота использований, документ, ADR (`sdd.py`), правила.
5. Подтверждение: применить → коммит на ветке, файлы изменены; отклонить → без изменений.
6. Повтор: `повторить` и повторное применение diff. 7. Сбои: облако 503, ошибка инструмента,
предел кругов. 8. Метрики без текстов.

## 5. Тесты (до кода модуля)

`test_files.py`: сервер (границы путей, пределы, поиск, оглавление, черновик, diff),
workspace (клон во временном репозитории, база, применение, отклонение, оригинал не
тронут), проверка находок и черновика, цикл ассистента на заглушке модели (вызовы, предел
кругов, итог), задача и повтор, консоль, API веба.

## 6. Сценарий показа

1. `/chat`: «Найди все места, где портал отправляет уведомления сотрудникам, и опиши, как
   они связаны» — ход: список, поиск, чтение 4–6 файлов; карточка находок с цитатами.
2. «На ветке случаев в urls.py добавлен маршрут — обнови документацию» — ход, diff
   справочника, «Применить» → коммит на ветке ассистента.
3. «Составь ADR о решении … по последним коммитам» — новый файл ADR в diff, проверка
   формата; «Отклонить» — ничего не изменилось.
4. «Проверь код на соответствие конституции» — нарушения с цитатами и правки.
5. Консоль: `--файлы-задачи`, `--файлы-повторить` — те же файлы.

## 7. Смета

ds-flash: цель ≈ 30–80 тыс. входных токенов ≈ $0,01–0,03; набор 10 целей × 2 + судья ≈
$0,5–1; отладка и показ ≈ $1.

## 8. Порядок работ и ворота

0. Ворота 0: A-1 (3 пробные цели ds-flash с черновым сервером), A-2 (правка заменой на 2
   документах), A-3 (`tools/sdd.py` в клоне), A-4 (ветка случаев и эталон).
1. Копия, сервер `files`, задача и черновик (тесты первыми).
2. Ассистент, проверка, консоль; набор целей. **Ворота 1** — SC-07.
3. Веб `/files`, браузер.
4. Проверки: `check_files.py`, `check_cli.py` часть 34, `run_tests.py`.
5. Показ, документы, коммит, свежий клон.

## 9. Риски

| Риск | Мера |
|---|---|
| модель пишет вне проекта или в секреты | у сервера нет таких путей: проверка в сервере, тест |
| правка без подтверждения | черновик вместо записи по построению; тест «отклонить» |
| рабочая копия владельца задета | свой клон, проверка HEAD и статуса до/после |
| модель «цитирует» несуществующее | проверка цитат кодом, «не подтверждена» |
| цикл не сходится / дорого | предел кругов и токенов, итог по собранному, метрики |
| diff не применяется | `git apply --check` до показа человеку |
